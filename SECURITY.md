# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use [GitHub private vulnerability reporting](https://github.com/DrDeathLabs/BuildLLM/security/advisories/new) to send the affected component, reproduction steps, impact, and any suggested mitigation directly to the maintainer.

Do not include credentials, private datasets, proprietary training data, or personal information in a report.

## Supported version

Security fixes are applied to the current `main` branch and the latest published release. Older tags may not receive separate fixes.

## Training-data safety

BuildLLM downloads and processes external corpora. Review source licenses and reports, inspect accepted and rejected documents, and do not add confidential or regulated data to a public corpus configuration.
